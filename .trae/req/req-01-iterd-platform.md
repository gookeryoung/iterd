# req-01 IterD 平台

来源：用户提供的《IterD 技术需求说明（AI 开发启动用）》（2026-10-10）。
定位：面向工程设计领域的产品迭代式开发平台，管理设计产物（图纸/模型/技术规范/仿真结果）从需求到基线的工程化闭环。
优先级：P0（MVP）→ P1 → P2 → P3，详细技术方案见 `.trae/designs/iterd-platform.md`。

## 1. 项目与迭代管理

- [ ] 项目/子项目多级层级管理（P0）
- [ ] 迭代周期定义：编号、目标、时间窗、状态机（规划中/进行中/已关闭）（P0）
- [ ] 迭代下挂接设计产物（P0）
- [ ] 基线管理：迭代通过后建立基线，锁定产物版本（P0）
- [ ] RBAC 权限：项目级角色控制（设计师/评审人/管理员）（P0）；迭代级权限（P2）

## 2. 设计产物管理

- [ ] 多格式文件上传/下载：DWG/DXF/STEP、PDF/Markdown、模型文件（P0）
- [ ] 版本控制：元数据版本号 + 内容寻址存储，支持历史版本回溯（P0）
- [ ] 元数据管理：关键属性（材料/尺寸/公差等）入库（P0 手动录入 + JSON 扩展字段；P1 文件自动解析）
- [ ] 在线预览：缩略图 + Markdown/PDF 渲染（P0 基础版）
- [ ] 产物关联：同一迭代内产物间建立关联（如零件图→装配图→技术规范）（P0）
- [ ] 版本差异对比（P1 文本类；P2 元数据 diff）

## 3. 静态规则检查引擎

- [ ] 规则条目 CRUD，按分类组织（制图规范/尺寸公差/材料规范/工艺约束）（P0）
- [ ] 规则集配置：规则组合绑定项目或迭代（P0 单规则集；P2 多规则集）
- [ ] 检查器适配器机制：每类规则对应检查器实现，可扩展接入（P0 协议 + 进程内注册；P2 独立部署）
- [ ] 批量执行：对迭代下所有产物批量检查（P0）
- [ ] 结构化报告：问题位置、严重级别（错误/警告/提示）、违规描述、关联规则 ID（P0）
- [ ] 检查结果历史对比：同产物不同版本结果对比与改进趋势（P1）
- [ ] 检查任务异步执行 + WebSocket 进度推送（P0）

## 4. 动态仿真验证

- [ ] 求解器适配器统一接口，屏蔽求解器差异（P1，含 mock 求解器）
- [ ] 仿真任务模板化定义：输入文件、求解参数、预期输出、通过判据（P1）
- [ ] 任务调度：优先级队列，支持串行/并行执行（P1 单机；P3 集群/容器）
- [ ] 结果标准化：不同求解器输出统一为结构化数据（位移/应力/温度场）（P1）
- [ ] 自动评估：结果与目标值/历史版本对比，输出通过/不通过及偏差量（P1）
- [ ] 结果可视化：云图缩略图、关键指标曲线、对比报表（P1）
- [ ] 多求解器适配 + HPC 集成（P3）

## 5. 变更与评审（ECR/ECN）

- [ ] 变更请求 ECR：问题来源、影响范围、建议方案（P2）
- [ ] 变更通知 ECN：审批通过后生成变更单，关联受影响产物（P2）
- [ ] 评审流程：指定评审人、在线评审意见、通过/驳回（P2）
- [ ] 变更追溯：变更→原因→影响产物→规则/仿真结果全链路可查（P2）

## 6. 数字线程（追溯服务）

- [ ] 溯源 ID 体系：产物、规则、仿真、变更分配全局唯一 URN（P0 起随业务动作分配）
- [ ] 关联关系存储：需求↔设计↔规则结果↔仿真结果↔评审记录关联图（P2）
- [ ] 追溯查询：给定任一节点向上/向下追溯全链路（P2）
- [ ] 图谱可视化（React Flow）（P2）
- [ ] 图数据库 Neo4j 替代关系表（P3，可选）

## 7. 通知与审计

- [ ] 审计日志：所有写操作记录用户/时间/前后值（P0）
- [ ] 事件总线：关键操作（迭代关闭/检查完成/仿真完成/评审通过）发布事件（P1）
- [ ] 站内通知 + WebSocket 推送（P1）
- [ ] Webhook 通知渠道（对接企业 IM）（P1）

## 8. 非功能需求

- [ ] 任务失败可重试（框架级，P0）
- [ ] 安全：JWT 鉴权、防越权、传输加密（P0，HTTPS 由部署层终结）
- [ ] 结构化日志 + 任务状态监控（P0 日志；P1 面板）
- [ ] Docker Compose 部署（P0 开发形态；P3 生产化）

## 9. 验收标准（P0）

1. `uv sync --extra dev && make check` 全绿（lint + typecheck + cov ≥ 95%）。
2. `iterd seed` 注入演示数据后，`iterd serve` 可完成：登录 → 建项目/迭代 → 上传产物（含版本） → 建规则集 → 发起批量规则检查 → worker 执行 → 查看结构化报告 → 建立基线，全流程无 500。
3. 所有写操作在审计日志中可查。
