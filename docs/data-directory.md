# iterd 数据目录结构说明

iterd 的全部用户可写数据统一存放在数据根目录 `~/.iterd`（Windows 为 `C:\Users\<用户>\.iterd`），参考 cndb 的"用户数据根目录"设计理念：代码与数据彻底分离，应用升级、重装、迁移均不影响数据；设置环境变量 `ITERD_DATA_DIR` 可整体替换数据根目录（覆盖后其下所有子目录与默认数据库路径一并切换，常用于测试隔离与便携部署）。

## 目录树

```
~/.iterd/
├── config/                    # 配置文件目录
│   └── .env                   # ITERD_ 前缀环境变量落地文件（首次启动自动创建空目录）
├── data/                      # 数据库目录
│   └── iterd.db               # SQLite 数据库（主数据，lifespan 自动建表）
├── objects/                   # 产物内容寻址存储
│   └── {sha256 前 2 位}/{sha256}   # 产物文件按内容哈希存储，版本不可变、同内容去重
├── backups/                   # 备份归档默认输出目录
│   └── iterd-backup-<版本>-v1-<UTC 时间戳>.tar.gz
├── tmp/                       # 运行时临时文件（备份/还原的归档拼装中间目录，可随时清空）
├── cache/                     # 运行时缓存（可随时清空，删除不影响正确性）
└── logs/                      # 日志文件目录
```

## 各目录职责与访问权限

| 目录 | 用途 | 存储内容 | 写入方 | 访问权限要求 |
|---|---|---|---|---|
| `config/` | 配置 | `.env` 配置文件 | 用户手工 / 部署工具 | 仅当前用户可读写；含密钥类配置，禁止放宽为组/全局可读 |
| `data/` | 数据库 | `iterd.db`（SQLite） | 应用进程（serve/seed/worker） | 仅当前用户可读写；备份后可外部只读访问 |
| `objects/` | 对象存储 | 产物文件（内容寻址） | 应用进程（上传产物版本） | 仅当前用户可读写；文件不可变，禁止手工改名/编辑 |
| `backups/` | 备份归档 | `.tar.gz` 备份归档 | 应用进程 / `iterd backup` | 仅当前用户可读写；建议定期同步到异地/外部介质 |
| `tmp/` | 临时文件 | 备份还原中间目录 | 应用进程 | 仅当前用户可读写；可随时清空（归档完成后自动删除中间目录） |
| `cache/` | 缓存 | 运行时缓存 | 应用进程 | 仅当前用户可读写；可随时清空 |
| `logs/` | 日志 | 运行日志 | 应用进程 | 仅当前用户可读写；按需轮转清理 |

权限规范：数据根目录整体应仅限当前操作系统用户访问。Windows 下目录位于用户 Profile 内，默认继承用户级 ACL，无需额外配置；Linux/macOS 建议执行 `chmod 700 ~/.iterd`。禁止将 `~/.iterd` 置于多用户共享路径下。

## 目录创建时机

`iterd` 包被导入时（`iterd.core.config` 模块加载）即自动创建默认数据目录树及全部子目录，因此 `iterd serve` / `iterd seed` / `iterd worker` / `iterd backup` 的首次运行无需手工建目录。设置 `ITERD_DATA_DIR` 覆盖时，`data/`、`objects/`、`backups/`、`tmp/` 等子目录按需自动创建。

## 维护要求与异常处理

| 场景 | 处理方案 |
|---|---|
| 磁盘空间不足 | 优先清理 `tmp/`、`cache/`；备份占用过大时降低 `ITERD_BACKUP_KEEP`（默认 30 份） |
| `iterd.db` 损坏 | 从 `backups/` 最近归档还原，操作见《备份还原操作手册》（docs/backup-restore.md） |
| `objects/` 与数据库不一致 | 对象按内容寻址不可变，以数据库中的 storage_key 为准做垃圾回收（当前版本未内置 GC，手工清理前必须先备份） |
| 数据迁移到新机器 | 拷贝整个 `~/.iterd` 目录，或使用备份归档在新机执行 `iterd restore` |
| 日志持续增长 | 直接清理 `logs/` 下历史日志；应用重启后自动重建 |
| `config/.env` 丢失 | 按 `.env` 模板重建（全部配置项均有默认值，缺失仅影响覆盖项） |
